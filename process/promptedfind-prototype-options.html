The prototype itself — how Ask should function on YouTube

Companion to the repo review. Two decisions about the PromptedFind mockup, each shown inside a schematic watch page. Part 1 — the Ask interaction: what happens between typing a question and landing in a moment. Part 2 — where the semantic decomposition lives: a second timeline, the native scrubber, or an always-on strip. These choices also feed Option B on the case-study page: the stronger the decomposition reads in the prototype, the stronger “Semantic Decomposition” reads as a named method.

Part 1 · The Ask interaction

Today the panel is a one-shot search: the query is erased on submit, results say “click a highlighted timeline segment,” and the answer lives somewhere else. The case-study page promises “the query stays visible while you watch” — the prototype currently breaks that promise. Real YouTube’s AI “Ask” is conversational: starter chips, the question persists as a chat turn, answers carry tappable timestamps.

Option 1A · Polished search panel (smallest change)

Keep the search model, fix the behavior: the query stays in the input after submit, results are clickable moment cards right in the panel (not an instruction to go click elsewhere), starter chips replace the keyword hint, and the debug copy (“1 track rendered”, “Mock data only”) moves to the console.

Option 1B · Conversational Ask (YouTube parity)

Match how the real feature behaves: starter chips on open, each question becomes a chat turn, the answer is a short synthesized sentence with inline moment chips, and follow-ups refine within context. The case-study claim “the interface is a co-pilot, not a one-shot lookup” becomes literally true.

Part 2 · Where the decomposition lives

Today segments render on a second timeline below the player, only after a query — idle state is an empty strip, and the page ends up with two playheads (native scrubber + custom). The concept says decomposition is a property of the content; the UI says it’s a property of the search.

Option 2A · Native scrubber only (maximum platform fidelity)

No second timeline. Segments render as chapter marks in the video’s own progress bar (the gap-divided scrubber every YouTube user already reads), and query matches glow. Hover shows the segment title exactly like chapter previews.

For

  • Zero invented chrome — borrows YouTube’s own chapter vocabulary (“borrow, don’t invent”)
  • One playhead, one timeline, no duplicated state

Against

  • Segment labels disappear until hover — the decomposition itself becomes invisible
  • Weakest expression of the Semantic Decomposition story; looks like “chapters, highlighted”
  • Hard to fake convincingly over a native <video controls> element — needs a custom scrubber anyway

Option 2B · Always-on decomposition strip (the concept, visible)

The strip below the player is always populated — the talk arrives pre-decomposed into labeled, color-coded category lanes (Problem / Entry systems / Descent & landing / Program), Video-Tape style. Asking doesn’t create segments; it dims the ones that don’t match. Idle, it’s a map of the talk; queried, it’s the answer’s shape. Gaps between indexed ranges stay visibly unfilled instead of reading as dead space.

For

  • The concept becomes visible: decomposition is a property of the content, not of the search
  • Directly reuses the lane component vocabulary from Video Tape / view-spec — one visual language across all three surfaces (feeds Option B’s “one pattern, three surfaces” strip)
  • Idle state stops being an empty band; recruiters see the idea without typing anything
  • Kills the empty-timeline and two-playhead confusion in one move

Against

  • Departs from strict YouTube fidelity — it’s clearly an added layer (arguably the point)
  • Needs category labels added to data.js (9 segments → 9 segments + 4 lanes; small)
  • Vertical space: four lanes cost ~70px under the player

Working recommendation

1B + 2B, staged. Do 2B first (always-on lanes; mostly rendering changes against existing data) and the 1A behavior fixes (query persists, moment cards, chips, no debug copy) — that ships a coherent, honest prototype. Then upgrade the panel to 1B’s conversational thread as the second pass; it’s also what the Option 2 guided tour wants to walk through. Skip 2A: it trades away the one thing the project is named after. Behavior fixes that apply regardless: don’t auto-pause at segment end (nothing on YouTube stops playback for you), tooltip delay 1000ms → ~150ms, one brand spelling (“PromptedFind”, not “PromptFind”), remove the “Open video file” dev link.
