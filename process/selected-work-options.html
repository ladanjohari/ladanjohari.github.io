Brainstorm · not the live site

Four ways to arrange Selected Work, each shown with all 4 real projects so you can see how a live project and a “coming soon” one sit together. The shared rule in every option: same slots for every project, year always shown, status is one consistent trailing state — so it stays cohesive as you add, remove, or swap projects. Toggle OS dark mode to check both.

Option A — Unified rows (evolves what you have)

Your current list, made consistent. Every row = thumbnail · title · tags · year · status. The “Soon” rows keep their year and their slot; only the trailing state changes (Case study / Watch demo / Coming soon). Lowest risk, most scannable, add/remove = one <li>.

Option B — Card grid (thumbnail-forward)

Bigger visuals. Each project is a card with a large 16:10 thumbnail, then title, tags, and a footer with year + status. Grid auto-flows, so adding a 5th/6th project just fills the next cell. Best if your thumbnails/previews are strong; a missing preview simply falls back to the SVG.

Option C — Editorial index (typographic, no thumbnails)

The most senior / most resilient. Big titles carry it, no images needed, so a project with zero assets still looks intentional. Number + title + one-line description, year + status right-aligned. Hover nudges the row. This is the “confident, let the work speak” direction.

Option D — Register / table (densest, most scannable)

Maximum scannability for a recruiter skimming in seconds. Columns line up, status is a column not a structural change, degrades perfectly. Trade-off: reads more like a CV table, less like a designed portfolio.
