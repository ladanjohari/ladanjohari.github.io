Built July 19, 2026. One rule everywhere: this grades can I produce a working result with my tools, not can I write it cold from a blank file. Those are different tests. You kept failing yourself on the second one and calling real work fake.

A design engineer is a full designer who builds the front of the front-end — not half a designer and half a backend engineer. That framing decides every column below. The things you feel guilty about (databases, auth, algorithms) are not your job. The things you undercount (systems, motion, shipping, directing agents to real code) are.

Solid — claim these out loud in interviews

  • Hand-built interface systems from a design system

    Tokens, dark mode, responsive layout, concentric radii, 1px-rule discipline. Evidence: the whole live portfolio + the SI spec. This is your center of gravity.

  • Interaction & motion design — state models, hover/focus/reduced-motion behavior

    The SI 5-state model (motion = state, color = exception, Reduce Motion path), the hover-preview crossfades. You design motion at a senior level even when you can't hand-type keyframes from memory. Interviewers care about the first thing.

  • Turning ambiguous problems into working, deployed prototypes

    PromptedFind (semantic video nav, 74-min NASA demo), Session Indicator, the Substrate prototypes. This is the literal one-line job description of a design engineer.

  • Directing AI coding agents to ship real software

    Daily fluency with Claude Code as your build tool — reaching into real Swift, Python, SQLite. In 2026 this is a genuine differentiator, not a crutch. Name it as a skill.

  • Shipping & running live products

    A real Swift menu-bar app (process scan, 5 states, running), live sites on GitHub Pages, an animation capture pipeline (Puppeteer → ffmpeg). You ship. Many stronger coders don't.

  • Reading & modifying real code across HTML / CSS / JS / Swift / Python

    You read and steer your own Swift app, Python transcript parsers, a SQLite-backed store. Recognition is high even where blank-file recall is low.

  • User research & product-systems thinking

    The Substrate study (within-subject, think-aloud, 5 conditions, moderator script) and the substrate model itself (exit criteria, task trees, state of record). Real, claimable design work.

  • Basic unaided JavaScript, DOM level — and growing

    As of today: grab an element, wire a click, change text/classes, catch your own bugs. Small but real, and it's on an upward ladder. Don't call this nothing.
